PROBLEM 1: FAILURE PROVENANCE WAS LOST BEFORE THE FINAL DECISION
The existing tier-2 adjudicator returns failed_closed=True when unavailable,
over budget, timed out or unable to parse an answer. The old prepare phase
retained only the conservative 'contradiction' verdict. The policy engine could
then rank the writers and choose SUPERSEDE or REJECT, even though no semantic
classification had succeeded. The explicit force_contest path had the same
problem. A higher-authority incoming assertion could become active and justify
a dependent action following an unavailable adjudicator.

Repair: PreparedDecision now carries failed-closed atom IDs with their reasons.
The authoritative commit phase gives these IDs, and explicit forced IDs,
precedence over cached verdicts and structural classification. The policy engine
maps them directly to CONTEST before ordinary ranking. Existing aggregate
CONTEST handling prevents supersession/reinforcement and marks the incoming
and affected existing atoms contested. Audit records retain the failure reason.
Only neighbours still present in the authoritative read participate. No network
operation was added inside a transaction, no schema was changed, and the
existing transaction retry wrapper remains the sole production commit path.

PROBLEM 2: PRIVATE RECALL DID NOT IMPLY PRIVATE ACTION INPUTS
Recall hid another agent's private atom, but the action resolver selected it
again without its ownership restriction. It could justify an action or appear
in a contested-action explanation; a selected value could enter the derived
action-log payload. A hidden contested atom could also block an otherwise valid
shared-memory action and expose its content through the reason.

Repair: the shared action resolver filters another agent's private atoms before
gate evaluation, selected values, explanations or derived audit payloads are
constructed. This applies uniformly to all three modes. An action depending
only on hidden private memory receives the existing blocked_missing result.
The owner can still use their private memory; shared memory still works; the
owner's contested private memory still blocks their action. Final review also
rejects a missing, blank or non-string action identity before any query;
malformed private owners never establish ownership, and unrecognized
visibility values are denied in action resolution and recall. This hardens
direct SDK inputs, whose dataclass annotations do not enforce runtime types.
No authentication or role-permission redesign was added.

FINAL REVIEW OF TEST DESIGN
The fixtures never choose a policy result or action gate. Those decisions are
computed by production remember/_prepare/_commit, engine.resolve and act code.
The recording store only supplies rows and records/applies known SQL statement
parameters. Assertions check actual returned resolutions/gates, reasons,
justifying IDs, generated payloads and absence of supersede/reinforce writes.
Four direct policy tests use no store fixture and make resolve_pair raise if
forced decisions attempt normal ranking. Tests also prove that invalid action
IDs produce no queries/logs, and that two missing IDs do not establish private
recall ownership. This is strong code-path regression evidence, not SQL or
database verification. A valid matching unregistered ID is deliberately still
accepted: the repair is not represented as identity authentication.

WHAT RAN AND WHAT WAS MOCKED
Real executed code: Adjudicator parsing/error/budget behavior; prepare and
commit callbacks; policy resolution; atom/write parameter generation;
conflict-record generation; recall visibility; action gate and action audit
payload construction; existing pure unit tests.

Synthetic components: scripted nearest-neighbour rows, a recording store that
models only known statement shapes, an in-process transaction adapter, one
constant embedding vector and provider responses/errors. The recording store
is not a SQL engine. It does not prove CockroachDB query validity, persistence,
serializability, retry behavior under real contention, vector recall or crash
recovery. No real booking or external side effect occurred; executed=True in
controls refers only to the repository's simulated action result/log.

No live/paid LLM or third-party attack target was contacted. No real personal
data was used. The runner removes cloud/database credential variables and
blocks socket connections. Test strings and the private marker are synthetic.

ACCESS-CONTROL LIMITS
The SDK still trusts a well-formed caller-supplied agent ID, workspace and
required_keys.
An untrusted caller allowed to impersonate another ID or omit dependencies is
outside this repair's guarantee. This does not add authentication, capability
binding, role-visibility enforcement for actions, audit-endpoint permissions,
tenant identity verification or sanitization of caller-supplied payload text.
It prevents this code path from deriving values/reasons from another agent's
private atom. Shared and role visibility otherwise retain existing behavior.
Database query filtering and all database integration remain unverified here.
